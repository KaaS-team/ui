# U1: Tokens and CSS layers for the shared design system

## What I built

- `css/tokens.css`: final values for every `--ui-*` token. Light is the default. Dark comes from `prefers-color-scheme`. `data-theme="light"` or `data-theme="dark"` on `<html>` forces a theme and sets `color-scheme` to match.
- `tokens.json`: three new colour tokens, `--ui-hover`, `--ui-border-strong` and `--ui-accent-hover`. No token was renamed or removed.
- `css/base.css`: reset, type scale, links, focus ring, selection, reduced motion. It also holds layout primitives: `.ui-stack`, `.ui-row`, `.ui-grid`, `.ui-card`, `.ui-visually-hidden`, `.ui-num` and `.ui-muted`.
- `css/shell.css`: the app frame with side nav, optional `.ui-topbar` with breadcrumbs, and content. It also styles page header, section, stat, attention and empty. At 720px and below the nav becomes a top strip that scrolls sideways, with no script.
- `css/table.css`: a dense table with 36px rows and a sticky header inside `.ui-table-wrap`. Row states are hover, `aria-selected`, `data-status` (a 2px edge) and `aria-disabled`. Numbers in `.ui-num` cells are right aligned and use tabular figures.
- `css/controls.css`: buttons in four variants (primary, secondary, ghost, danger) plus a small size, with hover, active, focus and disabled states. Also input, select, textarea, field help and error, checkbox and radio, toggle (`role="switch"`), segmented control, and approval.
- `css/chip.css`: chips for pass, wait, fail, info and neutral.
- `css/log.css`: a monospace log with line numbers and levels from `data-status`. A caret shows while `aria-busy="true"` is set, and the log scrolls inside its own box.
- `css/timeline.css`: a run timeline with a status marker on a rail. The wait marker pulses. Each step shows its time and an optional `.ui-timeline-duration`.
- `css/demo.html`: one static page that shows every layer. It has no inline style and no script.
- `test/contrast.test.mjs`: computes the WCAG contrast of 78 pairs in each theme. Each pair is a named test that prints its ratio.
- `test/layers.test.mjs`: checks that font size and font family come only from tokens. It also checks that the demo has no inline style and that every `ui-*` class in the demo is defined in a layer.
- `test/colours.test.mjs`: scans more file types (svg, js, mjs, ts, tsx) and more colour functions (hwb), and adds a `ceiling:` ratchet in `colour-allow.txt`.
- `test/tokens.test.mjs` and `test/css.mjs`: a block parser for the three token blocks. New tests check that the `data-theme='dark'` block equals the media block, that each theme sets `color-scheme`, that a layer never declares `--ui-*`, and that a `var()` may name only a token or a `--_*` local from the same file.
- `reports/cloud/U1/`: screenshots.

axe-core 4.10.2 ran on the WCAG 2.0, 2.1 and 2.2 A and AA tags plus best practice, in all four views. It found 0 violations. Forcing the theme also works: with the OS in light and `data-theme="dark"`, the body is `rgb(10, 10, 10)`, and the reverse gives `rgb(247, 247, 247)`.

To check that the tests catch real faults, I broke the CSS on purpose five times and each test failed:

- I set muted to `#999999`. The contrast test failed: muted on bg was 2.66:1.
- I changed one value in the `data-theme='dark'` block. The parity test failed.
- I added a raw hex colour, a px font size and a literal font family to a layer. The colour, font-size and font-family tests failed.
- I raised the ceiling in `colour-allow.txt` without adding an entry. The ratchet test failed.
- I added an inline `style` to the demo. The demo test failed.

## Decisions

- No files exist in `docs/sources/`, so I derived the values from the brief. The page is ink on near-white paper. The one accent is ink, as on Vercel and Linear. Blue is used only for focus and info.
- I tightened the type scale for dense dashboards. md went from 15 to 14, lg from 18 to 16, xl from 24 to 20 and 2xl from 32 to 28. The token names are unchanged.
- The dark values are written twice, in the media query and in `[data-theme='dark']`, because CSS cannot share one block between the two. A test keeps the two copies equal.
- `--ui-border-strong` marks the edges of inputs, checkboxes and toggles at 3:1 or more (WCAG 1.4.11). `--ui-border` stays light and is only for panel dividers.
- The danger button uses a solid `--ui-fail` fill with `--ui-on-accent` text. That pair is in the contrast test.
- Layers name their private variables `--_*`, for example `--_button-bg` and `--_marker`, so the `--ui-*` namespace means "token" only.
- The colour ratchet is a `ceiling:` line that must equal the number of entries. Adding an exception means raising the ceiling in a reviewed diff. A stale entry already fails the test, so the list can only shrink without that diff. This follows the idea of ai-bootcamp's check-structure.ts. No code was copied, so there is no notice entry.
- I left `color(` out of the colour pattern because it would flag Go and JS functions named `color`.
- Chips have no dot. The label carries the status, and the brief rules out decorative dots.
- `css/demo.html` ships in the npm package and is served at `/_ui/demo.html` by `ui.Handler()`. It is a static reference page.

## For U2 (templates I do not own)

These layer features need markup that the current partials do not emit:

- `.ui-topbar` and `.ui-breadcrumbs` in shell
- `.ui-nav-count`, `.ui-nav-heading` and `.ui-nav-foot` in nav
- `.ui-table-wrap`, `.ui-num` cells and row `data-status` in table
- `.ui-timeline-duration` in timeline
- `data-size="sm"` and the ghost and secondary variants in button
- `aria-invalid` with `.ui-field-error` in form

The approval partial already uses `data-variant="danger"`, and controls.css now styles it.

# U2: Go partials, catalogue and terminal theme

## What I built

- `templates/*.tmpl`: all 13 partials filled in, with accessible markup. Details:
  - `log` is an ARIA log region (`role="log"`) that takes keyboard focus. `Live` adds `aria-busy`, and an empty log says so.
  - `table` has loading (`aria-busy`, one busy row), error (`role="alert"`) and empty states. Its scroll wrapper is a labelled, focusable region.
  - `attention` covers title, why and actions. A fail status is announced as an alert. One action sits beside the text; several go in a row below it.
  - `approval` shows the commit SHA and a diff link. Each POST carries `csrf` and `sha`, and once decided it shows the decision instead of the buttons.
  - `form` ties help and errors to their field with `aria-describedby` and marks bad fields `aria-invalid`. It also has a form-level alert, and `ID` prefixes field ids so two forms on one page stay unique.
  - `button` turns a disabled link into a disabled button. `nav` takes a landmark `Label`. `head` adds `color-scheme` and extra stylesheets. `shell` gives `main` an id. `timeline` and `stat` have empty states.
- `data.go`: additive fields only. These are `Head.Styles`, `Nav.Label`, `Table.Loading/Error`, `Log.Live/Empty`, `Attention.Actions`, `Approval.SHA/DiffURL/Decided`, `Timeline.Label/Empty`, `Form.ID/Error`, `Field.Error` and `Button.Disabled`. No existing field changed.
- `catalogue.go` and `catalogue/`: `ui.Catalogue()` serves `/_ui/catalogue`, one page with every partial in every state (empty, loading, error, long text, many rows), built from sample data only. `catalogue/catalogue.css` lays out the grid of states using tokens only.
- `cmd/catalogue`: `go run ./cmd/catalogue -addr 127.0.0.1:8080` serves `/_ui/` and `/_ui/catalogue`.
- `term/`: the terminal theme. `term.Default` holds every colour and status token as a light and dark pair, read at start-up from the embedded `css/tokens.css`. There is no second copy. `term.Color` has the same shape as Lip Gloss v1 `AdaptiveColor`, so `lipgloss.AdaptiveColor(term.Default.Text)` converts directly. For v2, use `Pick(dark)`. `Theme.Status` maps a `ui.Status` to its foreground and background.
- `package.json`: `@kaas-team/ui` exports `ui.css`, `tokens.css`, `css/*`, `tokens.json` and `package.json`, and sets `style` and `sideEffects`. Its dev dependencies are `axe-core` and `playwright` (see below), and it has no runtime dependencies.
- Tests, all in `just check`:
  - `term/term_test.go`: token parity. tokens.css, tokens.json and `term.Theme` name the same tokens, and the theme covers exactly the `colour` and `status` groups. It caught U1's three new tokens on rebase. Other tests check that values match tokens.css and that `Load` rejects a missing or non-hex token.
  - `states_test.go`: each promised state of each partial.
  - `catalogue_test.go`: covers every name in `Names`, balanced HTML, unique ids, every `for` and `aria-describedby` target exists, catalogue CSS uses known tokens, and the package.json exports.
  - `cmd/catalogue/main_test.go`: the routes.
- `catalogue/axe.mjs`: the axe-core check of `/_ui/catalogue` in four views: light and dark at 1280x800 and 390x844. It is the `axe` recipe, now part of `just check`. `catalogue/screens.mjs` (`just screens`) takes the screenshots.

I checked that the new tests fail without the change. With `role="log"` removed from `log.tmpl`, `states_test.go` fails. With `for` removed from form labels, `axe` reports `label-title-only` and exits 1.

## Decisions

- **No Lip Gloss dependency.** AGENTS.md asks for `/eng-add-dependency` before any Go dependency, and that skill was not available here. `term.Color` matches Lip Gloss v1 `AdaptiveColor` field for field, so callers convert with no glue. The ui module stays dependency-free, so it still has no go.sum.
- **The theme reads tokens.css, not tokens.json.** tokens.json lists names only, while tokens.css holds the values. The parity test ties the three name lists together.
- **The theme covers the colour and status groups only.** Space, radius, type, font, shadow and motion mean nothing in a terminal.
- **The catalogue is a separate handler.** `ui.Handler()` still serves only CSS, so a product that mounts it does not expose the catalogue by accident. To show it, mount `ui.Catalogue()` at `ui.CataloguePath` and `ui.CataloguePath + "/"`.
- **The axe check is in the gate.** The `axe` recipe runs `npm ci` on first use, and on CI (`CI` set) it runs `npx playwright install chromium` before the check, so the current workflow needs no change. Versions are pinned to `axe-core` 4.14.0 and `playwright` 1.63.0, the build already installed in cloud sessions.
- **Outside my paths I edited one file: `justfile`.** I added the `axe` and `screens` recipes and put `axe` in `check`, because the brief asks for axe in the gate. I left AGENTS.md alone. Its command table still lists the gate as "fmt, vet, test, tokens, prose" and should gain "axe".

## New dependencies

All of them are npm dev dependencies, used only by the gate and never shipped:

- `axe-core` 4.14.0 (Deque, MPL-2.0, released 2026-10-05, about 3 MB unpacked). It is the standard accessibility engine. It is used unmodified and not ported, so the port licence rule does not apply.
- `playwright` 1.63.0 (Microsoft, Apache-2.0, released 2026-09-04). It is the same version cloud sessions preinstall, so it finds the browser that is already there.
